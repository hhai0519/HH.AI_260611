# ADR-002: 引入 Fencing Token 世代防護機制與鎖狀態 Row 保留

## 狀態
已通過 (Accepted)

## 背景
在分布式系統中，網路延遲或垃圾回收（GC Pauses）可能導致 Worker 雖然失鎖卻依然向儲存層或 API 發送寫入請求，進而覆蓋最新版資料。

## 決策
1. 分散式鎖表引入 `fencing_token` 欄位，這是一個單調遞增的 BIGINT 世代計數器。
2. 每次鎖被重新取得時，`fencing_token` 加 1。所有下游客戶端（如訊息出列、回覆）必須在 HTTP 請求與資料庫操作中帶上當前的 `fencingToken`。
3. 釋放鎖時不刪除 Row，而是將 `locked_by` 設為 NULL，並將最後持有的所有者與 token 記錄在 `last_owner` 與 `last_fencing_token` 欄位中，提供完整的審計歷史。

## 後果
- 下游 API 可有效阻斷過期 Worker 的延遲請求，達成端到端的分散式寫入安全性。
- 保留 Row 的設計提供了可靠的系統審計軌跡，有利於 SRE 調查失鎖事件。
