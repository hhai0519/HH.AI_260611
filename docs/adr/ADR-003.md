# ADR-003: 禁止 In-Memory Fallback 自動降級以避免腦裂

## 狀態
已通過 (Accepted)

## 背景
當 PostgreSQL 暫時失去連線時，系統原本會自動降級為 In-Memory 鎖模式。然而，在多實例部署環境下，各自獨立的 Bridge 會各自建立記憶體鎖，導致「雙主鎖」並引發腦裂。

## 決策
1. 實裝 `ALLOW_IN_MEMORY_FALLBACK` 環境變數。
2. 生產環境強制將其配置為 `false`。當資料庫斷開時，API 直接回傳 `503 Service Unavailable` 拒絕服務，寧可短暫不可用，也絕不妥協分散式一致性。

## 後果
- 杜絕了高併發多實例下的雙主腦裂風險。
- 系統的可用性（Availability）將直接取決於 PostgreSQL 的可用性。在資料庫發生 Failover 時，會有短暫的服務中斷，但保證了數據一致性。
