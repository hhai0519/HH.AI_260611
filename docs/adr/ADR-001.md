# ADR-001: 使用 PostgreSQL 作為時鐘 SSOT 與分布式行級鎖

## 狀態
已通過 (Accepted)

## 背景
先前分散式鎖在搶鎖與判定過期時，使用 Node.js 應用層的時間（`new Date()`），當多台伺服器或主機之間出現時鐘漂移（Clock Drift）時，可能導致鎖在尚未過期的情況下被誤判為已過期，引發多重搶佔與資料不一致。

## 決策
1. 將所有時間判定邏輯完全下放到 PostgreSQL，以資料庫的 `NOW()` 作為系統唯一可信時間來源（Single Source of Truth, SSOT）。
2. 在搶鎖 API 中使用 `SELECT ... FOR UPDATE` 施加行級排他鎖，防止高併發下的 Race Condition（ABA 問題）。

## 後果
- 徹底消除因時鐘偏移導致的腦裂或鎖提前釋放風險。
- 資料庫負載將隨著搶鎖與驗證頻率成比例增加，但對於微型超參數優化系統的併發規模而言完全在可控範圍內。
